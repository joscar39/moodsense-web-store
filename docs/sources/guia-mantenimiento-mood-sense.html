Guía de funcionamiento y mantenimiento

Cómo está hecha Mood Sense y cómo cuidarla

Qué hace cada parte de la tienda, con qué está construida, dónde está cada cosa y cómo agregar páginas nuevas. Escrita para que la entienda alguien que no programa y le sirva a quien sí programa.

1Cómo funciona, en una imagen

Cuando alguien abre la tienda en su celular, pasa esto:

NavegadorEl cliente ve páginas y toca botones
→
PáginasCarpeta app/: arman lo que se ve
→
Lógica del negocioCarpeta lib/: precios, stock, pedidos
→
ServiciosBase de datos, buscador, WhatsApp

Piénsalo como un restaurante. Las páginas son el salón: lo que el cliente ve. La lógica del negocio es la cocina: ahí están las reglas (cuánto cuesta, si queda stock, cómo se arma un pedido). La base de datos es la despensa: guarda productos, clientes y pedidos. El salón nunca va directo a la despensa: siempre pasa por la cocina, que verifica todo. Por eso nadie puede, por ejemplo, cambiar un precio desde su navegador: el precio lo pone siempre la cocina, leyéndolo de la despensa.

3Metodología de trabajo

  • Por fases: el proyecto se construyó en 8 etapas (0 a 7). Al terminar cada una se revisa con el dueño antes de seguir. El documento "Fases del proyecto" explica cada una.
  • Un solo proyecto ordenado por áreas ("monolito modular"): tienda, cuenta, admin y pagos viven juntos pero en carpetas separadas. Es más simple de publicar y mantener que varios sistemas sueltos.
  • Separación de responsabilidades: las páginas solo muestran, la lógica vive en lib/, y los componentes visuales no acceden a datos.
  • Seguridad por defecto: todo dato externo se valida, los permisos se revisan en el servidor (no solo escondiendo botones), el dinero se maneja en centavos exactos y el stock se aparta de forma que dos clientes nunca compren la misma última unidad.
  • Pruebas automáticas para lo crítico (precios, stock, pedidos, login), y cada error corregido suma una prueba.
  • Historial ordenado: cada cambio se guarda en git con un mensaje estándar (feat: función nueva, fix: corrección, docs: documentación…).
  • Simplicidad: se evita construir de más. Una función hace una cosa y se lee de arriba abajo.

4Mapa de carpetas

Carpeta / archivo Qué contiene
app/ Las páginas. Cada carpeta es una dirección del sitio (ver sección 5).
app/(shop)/ Tienda pública: portada, productos, carrito, checkout, búsqueda.
app/(auth)/ Pantallas de iniciar sesión y registrarse.
app/(account)/ "Mi cuenta" del cliente: perfil, direcciones, pedidos, deseos.
app/admin/ Panel de administración (solo administradores).
app/api/ "Ventanillas" del servidor que reciben pedidos del navegador (agregar dirección, crear pedido…). Solo reciben, revisan y llaman a lib/.
lib/ La lógica del negocio, por tema: catalog (productos), checkout (pedidos), inventory (stock), account, admin, auth, search, notifications (WhatsApp), validators (reglas de los formularios).
components/ Piezas visuales reutilizables, agrupadas por zona (home, catalog, cart, admin…).
components/ui/ Componentes base generados por shadcn. No se editan a mano.
app/globals.css Colores y tipografías de la marca.
prisma/ Estructura de la base de datos (schema.prisma), sus cambios históricos (migrations) y los datos de ejemplo (seed.ts).
e2e/ Pruebas automáticas que simulan a un cliente real en el navegador.
docs/ Documentos como este. Los PDF se generan desde docs/sources/.
.env / .env.example Configuración (claves, números, direcciones). .env.example explica cada dato; .env tiene los valores reales y nunca se comparte.
AGENTS.md, .agents/, CLAUDE.md Instrucciones para asistentes de IA (Claude Code y Antigravity). Contienen las reglas y el estado del proyecto.

5Cómo se construye una vista (página)

La regla de oro: la carpeta es la dirección

Dentro de app/, cada carpeta con un archivo page.tsx es una página. El nombre de la carpeta es lo que se escribe en la barra del navegador:

Archivo Dirección en el navegador
app/(shop)/page.tsx / (portada)
app/(shop)/cart/page.tsx /cart
app/(shop)/products/[slug]/page.tsx /products/cualquier-producto (los corchetes significan "variable")
app/admin/orders/page.tsx /admin/orders

Las carpetas entre paréntesis, como (shop), no aparecen en la dirección: solo agrupan páginas que comparten el mismo marco.

Los archivos especiales de cada carpeta

  • page.tsx: el contenido de la página.
  • layout.tsx: el marco que envuelve a todas las páginas de esa carpeta (por ejemplo, el encabezado y pie de la tienda están en app/(shop)/layout.tsx).
  • loading.tsx: lo que se ve mientras carga.
  • error.tsx: lo que se ve si algo falla.

Ejemplo 1: crear una página "Nosotros" en /nosotros

  1. Crear la carpeta app/(shop)/nosotros/ (dentro de (shop) para que tenga el encabezado y pie de la tienda).
  2. Dentro, crear el archivo page.tsx con este contenido:
import type { Metadata } from "next";

// Título que aparece en la pestaña del navegador y en Google.
export const metadata: Metadata = { title: "Nosotros" };

export default function AboutPage() {
  return (
    <div className="mx-auto max-w-3xl px-4 py-10">
      <h1 className="font-serif text-4xl">Nosotros</h1>
      <p className="mt-4 text-muted-foreground">
        Mood Sense es un concept store multimarca...
      </p>
    </div>
  );
}
  1. Guardar. Con el proyecto encendido (npm run dev) la página ya existe en localhost:3000/nosotros.
  2. Para que aparezca en el menú superior: abrir app/(shop)/layout.tsx y agregar en la lista navLinks una línea como { label: "Nosotros", href: "/nosotros" }.
  3. Para que Google la conozca: agregarla en app/sitemap.ts.

Ejemplo 2: una página que muestra datos de la base

Las páginas piden los datos directamente a una función de lib/, nunca a la base de datos por su cuenta: 

import { listProducts } from "@/lib/catalog/products";

export default async function OffersPage() {
  // La "cocina" (lib/) trae solo productos activos y en oferta.
  const { items } = await listProducts({ onSale: true, page: 1, perPage: 24, sort: "newest" });
  return <ProductGrid products={items} />;
}

Si la página necesita algo que todavía no existe en lib/, primero se agrega la función ahí (con su prueba si toca precios, stock o pedidos) y luego se usa desde la página.

Páginas privadas

  • Si la página va dentro de app/(account)/account/, ya está protegida: solo entra quien inició sesión.
  • Si va dentro de app/admin/, debe empezar llamando a await requireAdminPage(), igual que las demás páginas del admin. Esconder un botón no es seguridad: la verificación siempre se hace en el servidor.

Piezas visuales y estilos

  • Si un bloque se repite en varias páginas, va como componente en components/<zona>/ (nombre del archivo en minúsculas con guiones, por ejemplo product-card.tsx).
  • Colores de marca disponibles como clases: bg-navy, text-gold, bg-cream, text-ink. Tipografías: font-serif (Playfair, titulares) y la normal (Archivo).
  • Un componente base nuevo (por ejemplo, un selector) se agrega con npx shadcn@latest add select, nunca copiándolo a mano.

6Tareas de mantenimiento frecuentes

Quiero… Cómo
Encender el proyecto en mi computadora En la terminal de Ubuntu (WSL): cd ~/projects/moodsense-web-store, luego docker compose up -d y npm run dev. Abrir localhost:3000.
Cargar o editar productos, stock y precios Desde el panel /admin (ver el Manual de administración). No hace falta programar.
Cambiar textos de la portada components/home/ (por ejemplo hero.tsx tiene el slogan principal).
Cambiar textos del pie de página components/layout/site-footer.tsx.
Cambiar colores de la marca app/globals.css, sección de tokens (--navy, --gold…).
Cambiar el número de WhatsApp o una clave Editar .env (las explicaciones están en .env.example) y reiniciar. En la versión publicada: Vercel → Settings → Environment Variables → Redeploy.
Rehacer el índice del buscador npm run search:sync
Revisar que todo sigue funcionando npm run lint, npm test y npm run test:e2e. Si alguno falla, no publicar.
Cambiar la estructura de la base de datos Editar prisma/schema.prisma y correr npm run db:migrate (tarea para un programador).
Publicar en internet Ver el documento "Publicar Mood Sense".

7Reglas para mantenerla segura

  • El archivo .env nunca se sube a GitHub ni se envía por chat o email.
  • Nada secreto va en variables que empiezan con NEXT_PUBLIC_: esas las puede ver cualquier visitante.
  • Todo dato que llega de un formulario o un link se valida con las reglas de lib/validators/ antes de usarlo.
  • Cada función que lee datos de un cliente filtra por su usuario: un cliente nunca puede ver lo de otro, aunque adivine un enlace.
  • Las páginas y ventanillas del admin verifican el rol en el servidor, cada vez.
  • No se escriben datos personales (teléfonos, direcciones) en los registros del servidor.
  • Las contraseñas de prueba (admin1234) solo existen en la computadora de desarrollo.
  • Antes de publicar un cambio, deben pasar las pruebas automáticas.

8Trabajar con asistentes de IA

El proyecto incluye instrucciones para Claude Code y Google Antigravity en AGENTS.md y .agents/rules/. Ahí están las reglas del proyecto, el estado actual y las decisiones tomadas, así que cualquier asistente trabaja con los mismos criterios. Al pedirle cambios, basta con describir qué se quiere. El asistente sabe dónde va cada cosa y debe actualizar esas reglas cuando el proyecto cambia.

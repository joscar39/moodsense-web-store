Publicar Mood Sense en internet (temporalmente y gratis)

Cómo poner la tienda en una dirección pública para probarla desde cualquier celular o computadora, usando tu cuenta de GitHub, Vercel y Neon. Tiempo estimado: 45 a 60 minutos la primera vez.

1Por qué no se usa GitHub Pages

GitHub Pages solo puede mostrar páginas fijas, como un folleto: archivos que no cambian. Mood Sense es una tienda "viva": tiene base de datos, inicio de sesión, carrito, pedidos y panel de administración. Todo eso necesita un servidor que piense y responda, y GitHub Pages no lo tiene. Si se publicara ahí, se vería una página rota o vacía.

La alternativa equivalente es Vercel: también es gratis, se conecta directamente a tu repositorio de GitHub y publica una dirección del estilo mood-sense.vercel.app. Cada vez que se suban cambios a GitHub, la tienda publicada se actualiza sola. Para la base de datos se usa Neon, también gratis.

Tu código ya está en GitHub (repositorio joscar39/moodsense-web-store). Puede seguir siendo privado: Vercel lo lee igual con tu permiso, y nadie más ve el código.

2Qué necesitas antes de empezar

  • Tu cuenta de GitHub (la misma donde está el repositorio).
  • Una computadora con el proyecto funcionando (la copia de WSL), para preparar la base de datos una sola vez.
  • El VPN apagado mientras haces el paso 3 (si no, la conexión falla).
  • Los últimos cambios del proyecto subidos a GitHub (pídele a tu desarrollador que haga el "push").

3Crear la base de datos en Neon

  1. Entra a neon.tech y elige Sign up → Continue with GitHub.
  2. Crea un proyecto: nombre moodsense, versión de Postgres 16, región la más cercana a tus clientes (por ejemplo US East).
  3. En el panel del proyecto pulsa Connect. Activa la opción Connection pooling y copia la dirección que aparece (empieza con postgresql:// y contiene -pooler). Guárdala: es tu DATABASE_URL de producción.
  4. Abre la terminal de Ubuntu (WSL) y entra a la carpeta del proyecto: 
    cd ~/projects/moodsense-web-store
  5. Crea las tablas en Neon (reemplaza lo que está entre comillas por tu dirección de Neon): 
    DATABASE_URL="postgresql://...-pooler...neon.tech/neondb?sslmode=require" npx prisma migrate deploy
  6. Carga los productos de ejemplo y el usuario administrador, eligiendo una contraseña fuerte y nueva: 
    DATABASE_URL="postgresql://...neon..." SEED_ADMIN_PASSWORD="UnaClaveLarga-y-Unica-2026" SEED_USER_PASSWORD="OtraClaveLarga-2026" npm run db:seed
Importante: el sitio publicado será visible para cualquiera que tenga la dirección. Nunca uses las contraseñas de prueba admin1234 / cliente1234 en la versión publicada. El administrador entra con admin@moodsense.dev y la contraseña que elegiste aquí.

4Publicar en Vercel

  1. Entra a vercel.com → Sign Up → plan Hobby (gratis) → Continue with GitHub.
  2. Pulsa Add New… → Project. Si no ves el repositorio, pulsa Adjust GitHub App Permissions y dale acceso a moodsense-web-store.
  3. Pulsa Import junto al repositorio. Vercel detecta solo que es un proyecto Next.js: no cambies nada en "Build and Output Settings".
  4. Abre Environment Variables y agrega una por una las siguientes (nombre a la izquierda, valor a la derecha):
Nombre Valor Obligatoria
DATABASE_URL La dirección de Neon del paso 3 Sí
AUTH_SECRET Un texto aleatorio NUEVO de al menos 32 caracteres. Puedes generarlo en la terminal con openssl rand -base64 32. No reutilices el de tu computadora. Sí
NEXT_PUBLIC_APP_URL La dirección que te dará Vercel, por ejemplo https://moodsense-web-store.vercel.app. Si aún no la conoces, ponla después del primer deploy (paso 5). Sí
AUTH_URL La misma dirección que NEXT_PUBLIC_APP_URL Sí
NEXT_PUBLIC_CHECKOUT_MODE whatsapp Sí
WHATSAPP_OPERATOR_PHONE Número de la tienda, solo dígitos, con código de país y sin "+" (ej. 18095550100) Sí
CRON_SECRET Otro texto aleatorio largo (openssl rand -hex 32) Sí
ORDER_PAYMENT_EXPIRY_HOURS 48 No
MEILISEARCH_HOST / MEILISEARCH_MASTER_KEY Solo si contratas Meilisearch Cloud (ver sección 6). Sin ellas, la página de búsqueda muestra un aviso de "búsqueda no disponible" y el resto funciona. No
BLOB_READ_WRITE_TOKEN Lo agrega Vercel solo si activas Blob (sección 6) No
  1. Pulsa Deploy y espera 2 a 4 minutos. Al terminar verás la dirección pública (por ejemplo moodsense-web-store.vercel.app).
  2. Si en el paso 4 no conocías la dirección: ve a Settings → Environment Variables, corrige NEXT_PUBLIC_APP_URL y AUTH_URL, y luego en Deployments abre el menú (⋯) del último y elige Redeploy. Los cambios de variables solo se aplican al volver a publicar.
Tarea automática de pedidos vencidos: Vercel ejecuta una vez al día la limpieza que cancela los pedidos no pagados a tiempo (el plan gratuito permite una vez al día). Además, la limpieza corre cada vez que un administrador abre la lista de pedidos, así que nada queda colgado.

5Probar la tienda publicada

  • La portada, el listado de productos y la ficha de un producto cargan con imágenes.
  • Puedes crear una cuenta nueva e iniciar sesión.
  • Haces un pedido de prueba: carrito → checkout → aparece la confirmación con el botón de WhatsApp.
  • Entras a /admin con el administrador, ves el pedido y lo marcas como pagado o cancelado.
  • Abres /sitemap.xml y /robots.txt y responden.

Para compartirla, basta enviar la dirección de Vercel. Funciona en cualquier celular.

6Extras opcionales

Subir imágenes desde el panel (Vercel Blob)

  1. En tu proyecto de Vercel: Storage → Create Database → Blob → Connect al proyecto.
  2. Vercel agrega solo BLOB_READ_WRITE_TOKEN. Haz Redeploy.

Buscador inteligente (Meilisearch Cloud)

  1. Crea una cuenta en cloud.meilisearch.com (tiene período de prueba; luego es de pago).
  2. Copia el host y la master key a Vercel como MEILISEARCH_HOST y MEILISEARCH_MASTER_KEY.
  3. Carga los productos en el buscador desde WSL: 
    MEILISEARCH_HOST="https://..." MEILISEARCH_MASTER_KEY="..." DATABASE_URL="postgresql://...neon..." npm run search:sync

Aviso automático de pedidos por WhatsApp

Con solo el número, el aviso de cada pedido queda escrito en los registros de Vercel (Logs) y el pedido aparece en el panel. Para recibirlo como mensaje automático hace falta la WhatsApp Business Cloud API de Meta (variables WHATSAPP_CLOUD_API_TOKEN y WHATSAPP_CLOUD_PHONE_NUMBER_ID, explicadas en el archivo .env.example).

7Apagar la publicación cuando termines

Como es temporal, cuando ya no la necesites:

  1. Vercel: proyecto → Settings → General → al final, Delete Project. La dirección deja de funcionar. (Si solo quieres ocultarla sin borrarla: Settings → Deployment Protection → activa Vercel Authentication para todo el sitio; así solo tú, con tu cuenta de Vercel, podrás verla.)
  2. Neon: proyecto → Settings → Delete project. Se borran los datos de prueba y los pedidos que se hayan hecho.
  3. El código en GitHub y tu copia local no se tocan.
Datos reales: si personas reales hacen pedidos en la versión publicada, sus nombres, teléfonos y direcciones quedan en Neon. Bórralos (paso 2) cuando termines la prueba, y no publiques la dirección en redes si todavía es solo una prueba.

8Problemas frecuentes

Qué ves Qué hacer
El deploy falla con un error de base de datos Revisa que DATABASE_URL sea la de Neon con -pooler y que hiciste el paso 3.
No puedo iniciar sesión / me devuelve al login Revisa que AUTH_SECRET exista y que AUTH_URL sea exactamente la dirección pública con https://. Luego Redeploy.
La tienda abre pero sin productos Falta el seed del paso 3.6.
"Búsqueda no disponible" Es normal sin Meilisearch (sección 6).
Cambié una variable y no se nota Siempre hace falta Redeploy después de cambiar variables.
